## The row

The SLC 500 row is new in this change and ships switched off. It is read-only by construction: ten tools in the `slc500_` namespace and a `rslogix-500` skill, with no write tool, no write switch and no controller session. It never edits a project, never writes an `.RSS`, `.SLC` or documentation export, and never goes online to a processor.

## The read paths

- **Text export.** An `.SLC` text export is the neutral-text path and works with no RSLogix 500 installation. The tools parse it for processor identity, program files, ladder rungs, data-file layout and referenced I/O addresses.
- **Documentation export.** An RSLogix 500 documentation export (`.EAS`, `.ERP`, `.EIC`, `.ESG`, `.CSV`) is the highest-fidelity machine-readable description of symbols, addresses and comments. The text export truncates symbols to 15 printable ASCII characters; the documentation export keeps the full symbol and description, so a cut-off symbol is a prompt to ask for it.
- **Binary `.RSS`.** Reading the binary container needs the RSLogix 500 automation server, and only the Professional or Developer edition exposes the read methods. When the server is absent the answer is `SOURCE_NOT_INSTALLED`; when it is registered but the edition or a transcript is missing the answer is `NOT_LICENSED`. A redacted transcript fixture proves the boundary, not a live vendor session.
- **`.ACH`.** APS-era material is detected, named and refused; re-save it from the era's tool or export a text version. No best-effort decode.

## The ten tools

`slc500_capabilities` reports what the host has; `slc500_open` opens a project path and returns identity and inventory, optionally comparing a second source; `slc500_ladder` reads one program file's rungs in neutral text; `slc500_find` searches symbols, data-file values and rung text; `slc500_io_census` counts referenced I/O by rack/slot cell, word and bit; `slc500_io_config` reports the processor chassis and modules or the honest limitation; `slc500_data_read` returns a value window from one data file; `slc500_processor` reads identity and status words; `slc500_database` parses a documentation export into address, symbol and description rows; `slc500_docs` serves the authored knowledge collection through the five documentation actions.

## Limits stated plainly

- The text export does not carry point-card identities, wiring or analog scaling. What it does not prove is reported under `coverage.unverified`, never filled in.
- Status words are read from the file or automation snapshot and explained by a `slc500_docs` page; the row does not recite a bit table from memory.
- When two sources disagree - a binary read and a text export, or two exports - the row returns both values and names both paths. A conflict is evidence to show the operator.
- The row describes SLC 500 semantics; it does not convert a project. Conversion belongs to the migration row, which owns the plan and the report.

## What is not proved yet

The parser and the automation boundary are covered by repository fixtures, including a redacted transcript. A full project read from an owner-licensed RSLogix 500 session is still the evidence that closes real-project coverage; until that transcript exists, treat the parser's coverage of an unfamiliar export as unproven rather than assume it. The product page owns the definitive scope once the row is wired into the release; this chapter describes the row as built.
